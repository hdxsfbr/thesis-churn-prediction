## What was built

`feedback.metrics` writes one row per metric into the existing `RUN_METRICS` table. Coverage is `(dispatched + queued) / (at_risk − holdout)`. Autonomy is autonomous dispatches over autonomous plus approved-and-dispatched. Audit completeness is the share of log rows whose R6.1 fields are filled; `PENDING` counts for response and outcome. The same step records LLM calls, template fallbacks on the email arms, the cycle duration, and treated and control churn rates when any outcome is already closed.

The runner's `metrics` step runs after `policy_update`, including when the agent is halted. This run's decide step is already finished, so the counts match the log it just wrote.

## Deviations

- No new migration. `V018__run_metrics.sql` already created `RUN_METRICS`. `V011` is a hole and was not reused.
- Treated and control churn rates are omitted when that arm has no closed outcome yet. A cycle's window has not elapsed, so those two rows appear only after `churn simulate` or a later close.
- Email fallbacks are template rows for `checkin_email`, `formulation`, and `retention_offer`. Escalation stays on its template and is not counted as a fallback. Holdout is not a fallback.
- The 45-day evaluation uses scale `small` (30,000 subscribers), which is the medium base T8 already uses. `settings.synth.scales` has no key named `medium`.

## Proposed ARCHITECTURE notes

- Run metrics are rows in `V018`'s `RUN_METRICS`, not a new migration. The names are `coverage`, `autonomy_rate`, `audit_completeness`, `llm_calls`, `llm_fallbacks`, `duration_s`, and, once an outcome is closed, `treated_churn_rate` and `control_churn_rate`.
- Coverage subtracts holdout from the at-risk denominator. `RUNS.at_risk` itself is still the full count.
- The `metrics` step follows `policy_update`. A halted agent still gets a metrics row.
- The evaluation run is scale `small` for 45 simulated days. On that draw, coverage exceeded 85% and autonomy exceeded 70% with the default thresholds.
