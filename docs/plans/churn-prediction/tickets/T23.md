## What was built

`docker/Dockerfile` builds one `python:3.12-slim` image, installs `libgomp1`, and runs as user `churn` (uid 1000). `docker-compose.yml` uses that image for `api` (`churn serve`) and `worker` (`churn worker`). Both read `.env`.

`.env.example` names every environment variable the package reads, plus the Snowflake account, user, password, private-key path, role, warehouse, and database. `CHURN_BACKEND` selects `duckdb` or `snowflake`. `Settings.load` now honors that variable.

`docs/deployment.md` is the clean-machine checklist and the "Switch to production views" section. That section names each contract view and tells the operator to edit `config/source_contract.yaml` only. `customers_pii` stays `pii: true` and is not rendered.

## Deviations

- `src/churn/settings.py` is not on the file list. `CHURN_BACKEND` had nowhere to land, so `Settings.load` reads it. Without that, the example would document a variable the process ignores.
- The image installs `.[snowflake]` so the same image can open the Snowflake backend. That extra is defined by T24. Docker was not run. R8.7 stays an operator check.
