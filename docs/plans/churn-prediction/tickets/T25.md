## What was built

The structlog processor in `obs/logging.py` already masks email and phone patterns and leaves `ts` and `level` alone. T9 shipped that processor. This ticket adds the proof that it holds on a full cycle, and that pipeline code never reads the PII source or a general HTTP client.

`test_no_pii_in_logs_tables_or_model_artefacts` runs the tiny pipeline at 2025-06-30 with a `FakeLLM`. It scans captured logs, the prompts the fake client stored, the feature frame, the training frame, `RISK_SCORES`, `INTERVENTION_LOG`, `OUTBOX`, `APPROVALS`, and the promoted model file. The exact values come from `THESIS_SYNTH.customers_pii` (`first_name`, `email`, `phone`, `address`). The scan also looks for email addresses, phone numbers, street addresses, and those first names as whole words.

`test_customers_pii_never_selected_by_pipeline_sql_or_code` greps `src/churn` and `sql` for `customers_pii`. `test_no_shopify_klaviyo_zendesk_or_http_clients` walks the AST of `src/churn` and rejects `requests`, `httpx`, `aiohttp`, `urllib3`, `urllib.request`, `http.client`, `shopify`, `klaviyo`, and `zendesk`. `anthropic` and `openai` stay allowed. `urllib.parse` is not banned.

## Deviations

- `logging.py` was not changed. The redaction processor is the one T9 already wires in before `JSONRenderer`.
- There is no `FEATURES` table. The scan uses the frame from `build_features` and the frame from `build_dataset`.
- `customers_pii` has `first_name` only. The names in the synthetic source are Alex, Sam, and Taylor. There is no last-name column to scan.
- `src/churn/synth` and `sql/synth` are skipped by the grep. The generator writes `customers_pii`, and `sql/synth/V003__synth_all_domains.sql` creates the table. Pipeline modules and the rest of `sql/` must not mention it.
- The phone regex is not applied to the model file. Joblib bytes decoded as text matched `211 122 5681`, which is binary noise. Exact emails, phones, and addresses from `customers_pii`, plus name word boundaries, are still checked in the model bytes. The phone regex still runs on logs, prompts, features, the training frame, and the ops tables.
- A passing scan on the tiny draw is not a live-data proof. The source is synthetic and the names are three first names.

## Proposed ARCHITECTURE notes

- The redaction processor in `obs/logging.py` is the T9 backstop. It masks emails and phone-like digit runs, skips keys `ts` and `level`, and does not rewrite an ISO date that the phone pattern also matches.
- There is no `FEATURES` table. A PII scan reads the `build_features` frame, the `build_dataset` frame, `RISK_SCORES`, `INTERVENTION_LOG`, `OUTBOX`, `APPROVALS`, captured logs, LLM prompts, and the promoted model bytes.
- `customers_pii` is created and written only under `sql/synth` and `src/churn/synth`. Pipeline code and other SQL must not name it. The contract view loader already refuses to render it.
- Allowed network clients in `src/churn` are the `anthropic` and `openai` SDKs, imported inside the LLM adapters. `urllib.parse` is not an HTTP client.
- The model artefact is checked for the exact synthetic PII strings. A phone regex on decoded joblib bytes is not a PII signal.
