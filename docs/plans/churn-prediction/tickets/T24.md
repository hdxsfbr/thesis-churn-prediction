## What was built

`SnowflakeWarehouse` implements the warehouse protocol. Credentials are read only from `SNOWFLAKE_ACCOUNT`, `SNOWFLAKE_USER`, `SNOWFLAKE_ROLE`, `SNOWFLAKE_WAREHOUSE`, `SNOWFLAKE_DATABASE`, and either `SNOWFLAKE_PASSWORD` or `SNOWFLAKE_PRIVATE_KEY_PATH`. A missing name raises `RuntimeError` that lists names and never values. The connector is an optional extra (`churn[snowflake]`) and is imported only when a live connection is opened, so the default CI install stays offline.

`merge_frame` checks the frame, writes it with `write_pandas` into a temporary stage (`quote_identifiers=False`), runs the existing `build_merge_sql`, and drops the stage. `query` lowercases column names, because Snowflake uppercases unquoted identifiers and the rest of the pipeline expects lowercase. `:name` placeholders are rewritten to `%(name)s` for the connector. A PEM private key is loaded as DER PKCS8 only on that path.

`churn bootstrap` on `backend: snowflake` executes `sql/bootstrap/roles_and_grants.sql` after migrations. That file creates `THESIS_SYNTH`, `CHURN_OPS`, and `CHURN_PRIVATE`, and the roles `CHURN_APP`, `CHURN_ANALYST`, `CHURN_APPROVER`, and `CHURN_SENDER`. The only `UPDATE` grant is `SELECT, UPDATE` on `CHURN_OPS.APPROVALS` for `CHURN_APPROVER`. `CHURN_SENDER` may `SELECT` the sender view. DuckDB bootstrap does not run the grants file.

Migration `V013__sender_view.sql` creates `CHURN_OPS.OUTBOX_FOR_SENDER` over `OUTBOX` rows whose status is `READY`. The default suite applies it through the existing migration runner.

## Deviations

- `warehouse/bulk.py` already had `build_merge_sql` and `check_frame`. T24 uses them and does not change that file.
- `open_warehouse` lives in `warehouse/duckdb.py`, which is not on the ticket file list. The minimum change routes `backend == "snowflake"` to `SnowflakeWarehouse.from_env()`.
- The grants file is Snowflake-only at runtime. DuckDB has no roles, so `churn bootstrap` runs it only when the backend is snowflake. The transpile test still parses it.
- The live smoke test is written and marked `snowflake`. This shell has no `SNOWFLAKE_*` variables, so it skips. A skipped smoke is not a live cycle and is not A10 proof.

## Proposed ARCHITECTURE notes

- The Snowflake extra is optional. CI installs `.[dev]` and never imports the connector. `open_warehouse` raises a clear install error only when `backend` is `snowflake` and the extra is missing.
- Query results are lowercased. Merge stages are temporary tables written with `quote_identifiers=False`, then the shared `build_merge_sql`. `:name` is the dialect placeholder; the connector receives `%(name)s`.
- `V013` is the sender view. The grants script is not a migration. DuckDB bootstrap does not execute it. The approver role's only write grant is `UPDATE` on `APPROVALS`.
- A green default suite, including a skipped `snowflake` test, is not live Snowflake proof.
