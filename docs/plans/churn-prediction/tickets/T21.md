## What was built

`churn.api` is a FastAPI app. Every route requires `X-API-Key` equal to `CHURN_API_KEY`. A missing or wrong key is 401. The key is read from the environment only.

`GET /health` reports the process. `GET /ready` is 200 when the warehouse answers, every migration file is recorded, and a promoted model loads. Otherwise it is 503 and the body lists the reasons. A warehouse with migrations and no model reports `promoted model missing`.

`POST /runs` accepts `kind`, `as_of`, and an optional `run_id`. It starts `run_cycle` on a background thread and returns the id. The cycle takes the warehouse lock, so a second trigger while that lock is held does not write another run. `GET /runs`, `GET /runs/{id}` (row plus `RUN_STEPS`), and `GET /runs/{id}/metrics` read what the cycle wrote. `GET /config/runtime` returns the validated config, including `errors` when a section does not parse.

`churn serve` opens the warehouse, applies migrations, and runs uvicorn.

## Deviations

- `warehouse/duckdb.py` is not on the file list. The in-memory connection is one object shared by the request and the background cycle, and DuckDB does not allow that without a lock. Each call takes an `RLock`, and a transaction holds it until commit or rollback.
- `fastapi` and `uvicorn` are main dependencies, pinned to `fastapi>=0.115.6,<0.116` so CI does not pick up the Starlette release that warns about `httpx`. `httpx` is a dev extra because `TestClient` needs it.
- pytest ignores the `anyio` `BlockingPortal` deprecation emitted by that Starlette. The suite's remaining warning is the existing Pandas4Warning.
- `POST /runs` takes an optional `run_id`. Without it the id is still `default_run_id(as_of, kind)`.
- Ready uses 503 when a check fails. Health does not look at the warehouse.

## Proposed ARCHITECTURE notes

- The API key is `CHURN_API_KEY` and is checked on every route, including `/health`. There is no approval route.
- `/ready` is 503 until the warehouse answers, the migration files are all recorded, and a promoted model loads. The body lists the reasons.
- `POST /runs` returns the id and runs the cycle on a thread. The cycle's lock is what stops a second trigger. `GET /runs/{id}` includes `RUN_STEPS`. Metrics are the `RUN_METRICS` rows.
- The DuckDB connection is guarded by an `RLock` because the thread and the request share it. A transaction holds that lock.
- `fastapi` is pinned below 0.116. A later Starlette warns about `httpx` at import, and that warning is not a product failure.
