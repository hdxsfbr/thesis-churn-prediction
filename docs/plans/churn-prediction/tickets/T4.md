### R2.3 No leakage

*Requirement:* features for a scoring date use only data available before that date.

| Aspect | Implementation | Test |
|---|---|---|
| Every source row is bounded by `:as_of` on event time and arrival time | Each domain's `visible_*` CTE has `<event_ts> < as_of AND loaded_at <= as_of`. `active` uses `started_at < as_of AND loaded_at <= as_of`. Refunds count only when `refunded_at < as_of`. `{{as_of}}` renders as `CAST(:as_of AS TIMESTAMP)` (bound parameter). | `test_feature_leakage.py::test_post_as_of_events_do_not_change_features` adds post-`as_of` rows and late-loaded rows in every domain and asserts the frames are equal. It also checks that moving `as_of` does change features. |
| Status flags do not leak (D1) | `status_paused` is event-derived and bounded like every other event. `status_past_due` is NULL unless `current_status=True`, which only the live run sets, when as_of is the run date. Training snapshots therefore never see today's status. This is the one documented exception, in `docs/data-contract.md` and ARCHITECTURE §6.2. | `test_post_as_of_events_do_not_change_features` (default flag) adds a resume after as_of, a late-loaded resume, a pause after as_of, a post-as_of order and a late-loaded order. `test_status_past_due_is_null_by_default`. |
