## 1. Requirement trace

### R3.1 Full-base scoring

*Requirement:* every active subscriber gets a churn probability in every run, with no sampling. After a run, the scored count equals the active count in the source, and the run log records both.

| Aspect | Implementation | Test |
|---|---|---|
| Active set defined once for scoring | `sql/features/subscriptions.sql`, CTE `active`: started before `:as_of`, loaded by `:as_of`, not cancelled before `:as_of`, status in `settings.scoring.active_statuses`. One row per subscriber (QUALIFY on the latest start). | `test_every_active_subscriber_scored` |
| Independent active count | `src/churn/features/builder.py::count_active` (distinct `subscriber_key`) | `test_every_active_subscriber_scored`: the test's own `ACTIVE_SQL` counts distinct `customer_id` straight from `THESIS_SYNTH.subscriptions`, so it is independent of the pipeline. |
| Every active row scored | `src/churn/model/score.py::score_frame`: one RISK_SCORES row per feature row, probability from the promoted model. `runner.run_cycle` merges them. | `test_every_active_subscriber_scored` (also checks the RISK_SCORES count, 0 <= churn_prob <= 1, and more than 10 distinct probabilities). |
| Both counts recorded | `runner.py` writes `RUNS.active_in_source` and `RUNS.scored`. Columns are in `sql/migrations/V001__ops_schema.sql`. | `test_every_active_subscriber_scored` asserts both on the RUNS row and on the returned `RunResult`. |
| Mismatch fails the run | `runner.py`: inside `wh.transaction()`, `scored != active` raises `RunFailed`. The scores roll back, and the `except` branch writes a FAILED RUNS row with both counts and `error_msg`. | `test_scored_count_mismatch_fails_run`: `score_frame` is patched to drop one row. ### Review addition: no label leak (`test_training_frame_has_no_label_leak`)

Not in the TASKS.md acceptance list. It was added after review found that status-derived features leaked the label. The source holds only today's status, so `is_paused` and `is_past_due` told the model which subscribers had churned.

- Fix: those features were removed. `sql/features/subscriptions.sql` now uses status only to decide who is active (comment in the `active` CTE), and `FEATURE_COLUMNS` has no status features.
- Test: it asserts that `is_paused` and `is_past_due` are not in `FEATURE_COLUMNS`. It builds the training frame with `build_dataset` and requires both label classes to be present. For each feature, no value that covers at least 5% of rows may have a single label, which would mean it perfectly separates the label.
- Relation to requirements: this protects the validity of R3.1 scores. The formal R2.3 leakage requirement (post-as_of events do not change features) is T4's.

## 3. Gaps and limits (honest notes)

1. **R3.5 is partial by design.** RISK_SCORES has no `top_factors` (T6), archetype (T7) or risk tier (T5) columns. T1 delivers score, model version, run id and history only.
2. **R3.1 count is not fully independent.** `count_active` repeats the active predicate of the feature SQL (review note c below). The check mainly catches losses in scoring or writing. It does not catch a wrong active definition. Only the test's own `ACTIVE_SQL` is independent, and it also repeats the same rule against the raw table.
3. **R8.2 is only the base.** Runner code carries a known-gap comment (R8.1): if an earlier run with the same `run_id` SUCCEEDED and a rerun then fails on a count mismatch, the rollback restores the earlier scores while RUNS says FAILED. No test covers this. Checkpointing and pinning arrive with T20.
4. **CLI not tested.** No test calls `churn synth`, `churn train` or `churn cycle` through typer. The tests call `run_cycle` and the training fixture directly, so the CLI wiring in `cli.py` is unverified by T1's tests.
5. **No test for point-in-time cutoffs in features.** The SQL applies `ordered_at < :as_of` and `loaded_at <= :as_of`, but no T1 test adds post-as_of rows. This is T4's R2.3.
6. **No model-quality assertion.** T1 only checks that scores are valid probabilities with variety. Accuracy (R3.6) is T8.
7. **CI was not run for this documentation change.** This document is a trace from reading the code, and the 6 tests were not re-run to produce it.

## 4. Non-blocking review notes for later tickets

- **(a) Double `load_promoted` call.** `runner.py` calls `load_promoted` once, for `RUNS.model_version`, and `model/score.py::score_frame` calls it again, for `RISK_SCORES.model_version`. If promotion changes between the two calls, the two versions could disagree. When model pinning lands (T20), load the bundle once and pass it into `score_frame`.
- **(b) Snowflake `;` splitting.** `warehouse/dialect.py::render_many` splits Snowflake-target SQL on `;`. This breaks on semicolons inside string literals. Revisit with the Snowflake backend (T24).
- **(c) `count_active` repeats the active predicate.** `features/builder.py::count_active` repeats the active predicate of the feature SQL, so the R3.1 check mainly catches scoring and write losses. Consider a differently-sourced active definition if the check needs to catch definition errors.
- **(d) Status features removed.** `is_paused` and `is_past_due` were removed to fix a label leak. Reintroduce them only from `subscription_events` (T4), never from the current-status column of `subscriptions`.
