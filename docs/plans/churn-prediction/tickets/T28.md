# T28 — Submission documents and the test report

## What was built

Operator documents:

- `docs/output-tables.md` lists every `CHURN_OPS` table and column from `sql/migrations`, the sender columns on `READY` outbox rows, and Metabase queries for score history, pending approvals, and the ready outbox.
- `docs/agent-logic.md` documents the runtime keys `tiers`, `gate`, `guardrails`, `holdout`, `policy`, and `outcomes`, plus the cycle order.
- `docs/runbook.md` covers daily operation, Metabase approvals, and one playbook per error class. The model playbook heading is the target of `docs/runbook.md#model-error`.
- `docs/decisions.md` restates A1–A12 for Andre to confirm.
- `docs/ai-usage-log.md` records what coding agents wrote and what they did not do.
- `docs/demo-script.md` is the recording script. The video itself is Andre's.
- `docs/test-results.md` is the generated report. CI overwrites it.
- `README.md` links those documents and lists `serve`, `worker`, and `report-tests`.

`churn report-tests --junit junit.xml` reads a JUnit file and writes the markdown report. A testcase with a `marker` property of `slow` or `scale` is copied into the slow-and-scale section. `.gitlab-ci.yml` runs the command after pytest and publishes `docs/test-results.md`.
