# T26 — Extensibility: module boundaries and a config-only intervention

- Feature: churn-prediction
- Ticket: T26 (issue #26)
- Branch: `ticket/T26`
- Covers: R8.5.

## What was built

`load_registry` already instantiated every dotted path in `config/interventions.yaml`. The docstring now states the extension rule: a new module plus one line in that file, and a default prior or the agent halts.

`tests/fixtures/dummy_intervention.py` is an email arm that is not listed in the committed config. The integration test appends its path for one cycle, adds the required weak default prior, and inserts `POLICY_STATS` rows (`alpha` 1000, `beta` 1) for each archetype and context bucket. The cycle chooses `dummy_email` and writes it to the outbox. The yaml, the policy row, and the inserted stats are restored afterwards.

`tests/unit/test_boundaries.py` walks the AST of `model`, `agent`, `execution`, and `synth`. `docs/extending.md` explains how to add an intervention type and a data source.

## Deviations

- The loader did not need a new mechanism. T11 already loads dotted paths. This ticket adds the proof, the boundary test, and the guide.
- Policy validation (T13) refuses a registry arm with no `policy.priors.default` entry. The test therefore writes a weak `[1, 99]` default for `dummy_email` as well as the `POLICY_STATS` rows. The weak prior would lose to the existing arms. The rows are what make the dummy win.
- `test_synth_imports_only_warehouse_and_contract` also allows `churn.settings`. ARCHITECTURE §3.1 lists settings, and `synth/generator.py` already imports it. That file belongs to T27.
- The agent test forbids `churn.execution.outbox` only. `cycle.py` imports `payload_hash` from `execution.approvals`, which does not write the outbox. The execution test forbids `churn.agent.policy` only. Approvals already import `agent.gate` and `agent.guardrails`.

## Proposed ARCHITECTURE notes

- §3.1: `tests/unit/test_boundaries.py` is the AST check. `model` does not import `agent` or `execution`. `agent` does not import `execution.outbox` (`payload_hash` stays in `execution.approvals`). `execution` does not import `agent.policy`. `synth` imports only `warehouse`, `contract`, `settings`, and its own package.
- §3 / §6.4: a new intervention is a subclass plus a dotted path in `config/interventions.yaml` plus a `policy.priors.default` entry. A `POLICY_STATS` row overrides that prior for one `{tier}:{tenure band}` bucket. `docs/extending.md` is the operator-facing version of this, including how a new source view is added in `source_contract.yaml` without pointing feature SQL at a physical table or at `customers_pii`.
