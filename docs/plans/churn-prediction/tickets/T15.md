# T15 — LLM-personalised content with a PII-free prompt and template fallback

- Feature: churn-prediction
- Ticket: T15 (issue #15)
- Branch: `ticket/T15`
- Covers: R4.4, R7.2, R8.1 (LLM failure).

## What was built

`churn.llm` is an `LLMClient` protocol with Anthropic (default), OpenAI and Fake adapters, a per-run `CallBudget`, and a tenacity retry of three attempts. The wait uses a `retry-after` hint when the provider sends one, otherwise a short exponential (0.05s, capped at 1s).

`agent.content.PromptContext` is the only payload a prompt may carry: archetype, factor labels, tenure band, blend names, goal categories, offer code, discount. `validate_message` rejects an empty draft, a draft over the length caps, a missing `{{first_name}}` merge token, an email or phone pattern, a missing offer code, a discount that does not match, and any other catalogue code.

`resolve_contents` calls the model for email arms only. Escalation stays on its template. Cache hits for the same intervention, archetype, factor labels and offer share one call and do not spend another budget slot. Timeout, provider error, a rejected draft, or a spent budget returns `intervention.template()` with `content_source=template`. A missing `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`, or a missing optional SDK, returns no client, so the cycle stays on the template and does not open a connection or retry.

`build_content` is unchanged and stays template-only. `decide` calls the model only when `run_agent` passes `settings`. A rerun of the same `run_id` reads the subject and body already stored for that `decision_id` and does not call the model again.

`config/settings.yaml` `llm:` is provider `anthropic`, model `claude-haiku-4-5`, `max_calls_per_run` 2000, concurrency 8, timeout 20s, three retries. Keys are environment variables only. `tenacity` is a main dependency. `anthropic` and `openai` are the optional extra `llm`.

## Deviations

- `src/churn/agent/cycle.py` is not on the T15 file list. `decide` gained keyword-only `stored` and `settings`. `run_agent` loads stored content and passes `settings`. Callers that omit `settings` (the existing policy tests) stay on the template.
- Subject and body are not columns of `INTERVENTION_LOG`, and this ticket adds no migration. Dispatch already writes them on `OUTBOX` and `APPROVALS`, and writes `content_source` / `content_ref` on the log. `load_stored` joins those by `decision_id`. That is the persisted copy a rerun reuses.
- `human_queue` never calls the model. Its template contains `{{subscriber_key}}`, which must not enter a prompt.

## Proposed ARCHITECTURE notes

- §6.4 step 5: the prompt whitelist is the frozen `PromptContext` (archetype, factor_labels, tenure_band, blend_names, goal_categories, offer_code, discount_pct). No identifier and no free-form blob. `{{first_name}}` is a merge token for the sender, not a value in the prompt.
- §6.4: email arms call the configured client (default Anthropic `claude-haiku-4-5`) through a pool of `llm.concurrency` (8), with a per-run budget and a within-run cache on (intervention, archetype, factors, offer). `human_queue` does not call the model. Three tenacity attempts, honouring retry-after, then the template and `content_source=template`. The same fallback covers a rejected draft and an exhausted budget.
- §6.4 / §6.1: the stored copy is `INTERVENTION_LOG.content_source` and `content_ref` plus the subject and body already on `OUTBOX` and `APPROVALS`. No new migration. A second `run_cycle` of the same `run_id` reuses that copy and makes no new model calls. `decide` stays on the template unless `run_agent` passes settings, and a missing key or missing optional SDK is the template path with no network attempt.
