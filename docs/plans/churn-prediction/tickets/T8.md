## 1. Requirement trace

### R3.6 Accuracy

*Requirement (PRD):* measured against historical churn with the agreed label and window (OQ1): top-risk-decile precision above 70%, and pre-cancellation recall above 60%.

*Design:*
- A1: the positive label is a voluntary cancellation within 30 days of the scoring date, and evaluation uses a time holdout of the last 3 months.
- §6.2: top-decile precision; pre-cancellation recall, which counts a churner as caught when their last score before cancelling was at or above the at-risk boundary; and a check of every target that prints MISS with a stated reason.
- §10: the slow test asserts the targets or xfails with the reason.

| Aspect | Implementation | Test |
|---|---|---|
| A1 label, with involuntary cancellations excluded | `evaluate()` builds the dataset with `build_dataset` (the same label as training); `_cancellations` reads voluntary cancels in the holdout | `test_report_states_label_window_and_holdout` |
| Time holdout of the last 3 months, never seen in training | `evaluate()` splits on the last `holdout_months=3` snapshot dates and refits a twin on earlier snapshots only; fails with `ModelError` if there are too few snapshots | `test_report_states_label_window_and_holdout` (the report states the label, the 30-day window and the holdout dates) |
| Top-decile precision | `top_decile_precision()`: precision of the top ceil(10%) of rows by probability, pooled across the holdout snapshots | `test_top_decile_precision_known_value` |
| Pre-cancellation recall | `pre_cancellation_recall()` / `pre_cancellation_breakdown()`: takes each churner's last score strictly before the cancel date and compares it with the boundary; a churner with no score counts as missed | `test_pre_cancellation_recall_uses_last_score_before_cancel`, `test_pre_cancellation_breakdown_splits_misses` |

**Measured outcome:** both R3.6 targets are **MISS** on the synthetic holdout. That outcome is reported honestly, as the design requires.

**Gap found and operator decision:** under the A1 label, top-decile precision cannot be higher than 10 × the base rate. The > 70% target can therefore only be reached if 30-day voluntary churn is at least 7%. On synthetic data the ceiling is 0.31, so the target cannot be reached there.

- The operator chose: "Also add a precision-ceiling note to ARCHITECTURE A1; T8 ok."
- I added that note to the A1 row (see §4).
- The PRD target is unchanged. Whether the real system meets it can only be judged on real Thesis data, and the R3.6 check reports it honestly on every run.

**Verdict for R3.6 (T8 scope):** the measurement, the honest check and the reporting have code and tests. The target values themselves are not met on synthetic data. The operator accepted this as recorded above.

## Revision 2 amendment (as built)

Code change that delivers the amended T8 text (PRD R3.6 Revision 2, ARCHITECTURE A1, §6.3, D4 to D9). The label is unchanged.

- **Files changed:** `src/churn/model/evaluate.py`, `src/churn/cli.py` (one line: the printed target line now shows each target's operator, `>` or `>=`), `tests/unit/test_evaluate_metrics.py`, `tests/integration/test_eval_report.py`, and the regenerated `docs/eval-report.md` and `docs/model-card.md`. No new migration: the new numbers go into the existing `metrics_json` and `targets_json` columns of `EVAL_REPORTS` (V005, unchanged), so the writes stay additive. No migration was needed; the highest on main is V014 and V015 is reserved for T29.
- **Splits:** `split_snapshots()` makes training, validation (`VALIDATION_MONTHS=3`) and holdout (`HOLDOUT_MONTHS=3`) by date. A snapshot is purged when its 30-day label window reaches the first snapshot of the next split. With month-end snapshots, a 30-day gap purges the snapshot before the split and a 31-day gap does not, so the validation split can hold fewer than three snapshots (on 'small': 2). The purged dates are listed in the report.
- **Evaluation model:** `train.fit()` on the training split only; never registered.
- **Metrics:** `top_share_precision` (top ceil(2%) rows), `top_decile_precision`, `top_decile_lift`, with ties ranked by `subscriber_key` then `snapshot_date`. `ceilings(b)` returns min(1, b/0.10), min(10, 1/b) and min(1, b/0.02) from the measured base rate.
- **Boundary:** `choose_boundary(validation)` takes the validation frame alone. It uses each churner's latest positive snapshot and returns the ⌈0.65·k⌉-th highest churner score. With fewer than 20 churners there is no boundary and no fallback: the recall target is MISS with that reason. It is reported as "Recommended at-risk boundary" only; `AGENT_CONFIG`, `CONFIG_SNAPSHOTS`, `RISK_SCORES` and the runtime tiers are untouched (`test_evaluate_does_not_write_agent_config`). The old `_at_risk_threshold` runtime-tier lookup and the fixed 0.20 boundary are gone.
- **Holdout recall and precision at the boundary:** recall keeps the cancellation-date method of the first T8 (last holdout score strictly before the cancel date) and its breakdown (caught, no score, below boundary). Precision at the boundary is churn labels among rows scored at or above it, with counts. This differs slightly from the ARCHITECTURE wording "latest positive snapshot in the split" for the holdout; the validation boundary follows that wording.
- **Targets:** `TARGETS` = top-2% precision > 0.50, top-decile lift >= 4.0, pre-cancellation recall > 0.60. `check_targets()` prints PASS or MISS with a reason (value and counts, "unreachable at base rate b" when the target is above its ceiling, a noisy-sample note for small counts, and the boundary reason).
- **Report and model card:** state the scale, split periods and row counts, purge, the three targets, the boundary, the ceiling table, why 0.70 was replaced, and the notes that synthetic accuracy is not real-world accuracy and that the 90-day impact target can only be checked after go-live. The model card says the production model is refit on all snapshots. The model card now shows the validation recall that selected the boundary, the holdout recall and the holdout precision at the boundary.
- **Tests:** the five named acceptance tests, plus `test_too_few_validation_churners_is_recall_miss_with_reason`, `test_splits_are_disjoint_ordered_and_purged`, `test_report_states_label_window_validation_and_holdout`, `test_report_shows_counts_ceiling_and_recommended_boundary`, `test_evaluate_does_not_write_agent_config` and the slow `test_targets_on_medium_synth`.
- **Result on 'small' (30k subscribers):** holdout 55,536 rows, 1,700 churn labels (b = 3.1%). Top-2% precision 0.671 (PASS), top-decile lift 5.65x (PASS, precision 0.173 against a ceiling of 0.306), recall 0.629 at a validation-chosen boundary of 0.030 with validation recall 0.712 (PASS; 1,120 of 1,781 caught, 64 no score, 597 below the boundary). Precision at the boundary 10.3%. This is synthetic data on the thin generator, so none of it says anything about real customers. T30 should compare its holdout row count (55,536) against this.
